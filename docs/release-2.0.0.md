# willGo 2.0.0：局域网双机模式

## 本次变化

在原有单机战斗模式之外，增加一台电脑采集、另一台电脑显示的双机模式。

两端安装同一个 Windows 安装包，仍先完成原有登录校验。双机模式默认关闭；旧配置升级后保持单机行为。

| 职责 | 数据端 | 显示端 |
| --- | --- | --- |
| 截图来源 | 这台电脑的桌面或预设区域 | 请求数据端截图，不截显示端桌面 |
| 麦克风与系统播放 | 采集本机选中的设备 | 接收两路音频，不打开本机音频设备 |
| 语音转写 | 不调用豆包 | 使用显示端配置的豆包凭证 |
| 问答、题干提取、解题 | 不调用问答模型 | 使用显示端配置的截图和对话模型 |
| 工作区 | 登录后后台运行，保留托盘和设置 | 保留现有问题列表、答案、代码与分栏 |
| 录音、转写和历史 | 不另存本次会话的录音或转写 | 保存到显示端配置的目录 |

## 首次连接

1. 两台电脑连接同一可互通局域网，安装同一个版本并登录。
2. 在采集电脑打开“设置 → 双机模式”，勾选“开启局域网双机模式”，角色选择“数据端”，保存。
3. 数据端问答窗口收起到后台。从右下角托盘重新打开设置，在“双机模式”中选择正确的局域网地址，点击复制图标。
4. 在另一台电脑开启双机模式，选择“显示端”，完整粘贴刚才的配对信息并保存。
5. 设置中及显示端窗口顶部出现“已连接”，表示配对成功。数据端此时仍不采集音频。
6. 显示端点击“开始战斗”，选择本次是否录音，才开始采集数据端的麦克风与系统播放。

数据端默认监听 TCP 端口 **38657**，可修改为 1024 至 65535 之间的未占用端口。首次启动监听时，允许 Windows 防火墙的专用网络访问。程序不会自动放开整台电脑的防火墙。

有多个网卡时，配对信息下拉列表提供不同本机地址；选择能被另一台电脑访问的那个。不要把回环地址 `127.0.0.1` 复制给另一台实体电脑。

## 在哪台电脑设置什么

### 数据端

- “语音设置”中的麦克风和扬声器，决定真正采集的设备。
- 未指定设备时，开始采集时读取本机 Windows 多媒体默认输入和输出设备。
- “模型设置 → 截图模型 → 截图范围”决定整个桌面或指定区域。
- 指定区域必须在数据端自己的屏幕上框选并保存。
- 数据端不需要配置豆包或问答模型密钥。相关识别、回答和归档配置使用显示端的设置。
- 采集中修改默认音频设备后，需要在显示端结束并重新开始战斗。

### 显示端

- 配置豆包凭证、截图模型、对话模型。
- 配置对话提示词、上下文提示词、麦克风触发词、断句停顿与回声过滤。
- 配置录音和转写保存目录。
- 显示端本机麦克风、扬声器和截图坐标不参与双机采集。
- 连接断开时不会退回使用显示端自己的设备或屏幕。

## 语音和提问

数据端将两路音频分别转换为 **16 kHz、16 位、单声道 PCM**，每路按约 100 毫秒组包，经局域网实时发送到显示端。

显示端分别为麦克风和系统播放建立豆包流式识别连接，沿用现有逻辑：

- 系统播放标为“对方”，最终句子自动提问。
- 麦克风标为“我”，只有命中触发词才自动提问；其他最终句子仍记入转写。
- 临时转写、最终结果去重、回声过滤、前两轮上下文继续生效。
- 新问题置顶，现有题目切换、答案滚动、代码排版保持可用。

两路音频未经压缩，持续传输的 PCM 合计约 **64 KB/秒，即 512 kbps**，另有少量协议开销。不是持续视频推流；只有触发截图时才发送图片。

## 截图与手机

以下入口都使用数据端保存的截图范围：

| 入口 | 行为 |
| --- | --- |
| 显示端 `Ctrl+Shift+S` | 请求数据端截图，在显示端新增截图题 |
| 显示端截图按钮 | 同上 |
| 数据端 `Ctrl+Shift+S` | 数据端截图并主动发送到已配对显示端 |
| 手机访问显示端页面 | 请求数据端截图，或直接在显示端提交文字 |
| 手机访问数据端页面 | 数据端截图发送给显示端；文字及预设问题也转发到显示端 |

显示端继续执行“视觉模型提取题目 → 显示题目 → 模型解答”的两阶段流程，答案仍包含思路、复杂度和代码等对应内容。

截图使用 PNG，单张上限 16 MB，通过约 48 KB 的小块发送。音频与截图分块共用加密连接，发送端逐块等待写入，避免一次把整张图片排在音频前面。网络带宽和延迟仍会影响实时效果。

## 录音和历史

“是否录制”仍在显示端每次开始时询问：

- 选择“是”：显示端生成一个 WAV 和同名 Markdown。
- 选择“否”：显示端只生成 Markdown。
- 选择“取消”：不启动数据端采集。

WAV 仍为双声道：左声道麦克风，右声道系统播放。文件名仍为 `willGo-年月日时分秒`；同秒重名自动追加序号。历史战斗读取显示端的保存目录。

原有边界不变：Markdown 记录语音转写，不自动保存完整问答答案或截图题；内存里的问题列表不是可恢复的会话数据库。

## 后台、重连与恢复单机

- 数据端登录后只保留托盘，不自动打开问答窗口或设置窗口。
- 双击数据端托盘或选择显示入口，打开连接与设置界面；退出仍使用托盘菜单。
- 显示端关闭主窗口仍是隐藏到托盘，不等于结束采集。
- “结束战斗”先停止数据端设备，再收尾云端转写与归档。
- 连接断开、音频队列拥塞或采集设备报错时，停止本次采集并提示；已有文件执行收尾。
- 显示端可在“双机模式”中点击“重新连接”。重连成功后处于待机状态，不自动恢复录音。
- 两端保存的角色与配对信息可跨启动保留。数据端监听身份保存在当前 Windows 用户下。
- 数据端地址或监听端口改变时，重新复制当前配对信息到显示端。
- 点击数据端“重置配对信息”会断开现有连接并更换凭据，旧配对信息失效，需要重新复制配对。
- 关闭“双机模式”并保存，停止原采集、断开双机连接，恢复本机截图和本机语音采集。

本版支持常见 IPv4 私有局域网地址及链路本地地址，采用复制配对信息的方式，不依赖 UDP 自动发现；不支持仅 IPv6 网络、公网中继、多台显示端同时连接、远程鼠标键盘控制或断线后自动恢复采集。

## 连接与配置保护

配对信息包含局域网地址、随机连接凭据和数据端证书指纹。显示端固定校验该证书指纹，通过 TLS 1.2/1.3 建立连接后再校验配对凭据。一个数据端同时只接受一个显示端，错误配对不会替换已连接的显示端。

语音和问答 API 密钥不发送给数据端。已保存的显示端配对信息、本机数据端证书和连接凭据使用 Windows 当前用户的 DPAPI 保护，不随标准安装包分发。

配对信息相当于本次设备连接凭据，应提供给要连接的电脑。重装系统或更换 Windows 用户后可能需要重新配对和填写服务密钥。

## 本次验证

- Release 编译。
- 现有战斗流程、截图工作区、设置、登录、排版、归档等回归测试。
- 同机两个独立服务实例通过真实 TCP/TLS 配对，测试错误凭据、错误证书、第二台显示端拒绝、音频序号、图片分块、重连和断线收尾。
- 双机链路接入本地模拟豆包 WebSocket，验证两路转写、触发词和显示端录音归档，不使用真实 API 额度。
- 本机真实默认 WASAPI 麦克风和系统播放采集，经 TLS 到显示服务和本地模拟识别端，验证设备、转换、传输与停止。
- 完整应用启动测试：保留登录门禁、数据端后台与托盘、配对后仍无问答窗口、关闭双机恢复主界面。

上述同机测试不能替代两台实体电脑之间的路由、防火墙、无线网络质量和实际云端延迟验收。首次双机实测应先验证连接，再测试一句语音和一张截图。
